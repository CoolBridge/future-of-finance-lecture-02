## Backend setup

1. Create a new Google Sheet for Lecture 02. Open **Extensions → Apps Script**, paste `Code.gs`, and replace `appsscript.json` (enable "Show appsscript.json" in Project Settings). Time zone must be `Africa/Lagos`.
2. Fill the CONFIG values above. Run `setupSheets()` once (creates Registrations, Polls, Feedback, Errors with headers).
3. **Deploy → New deployment → Web app**: Execute as *Me*, access *Anyone*. Copy the `/exec` URL into `register.js`.
4. Run `sendTestEmails()`; it sends all five templates, marked `[TEST]`, to the script owner only. Check rendering in Gmail and Outlook.
5. Run `setupTriggers()` once. It removes any old `processReminders` trigger and creates one daily trigger (runs between 09:00 and 10:00 Lagos time; Apps Script does not guarantee the exact minute).
6. After any code change, create a **new deployment version**; the `/exec` URL stays the same when you edit the existing deployment.

Recovery: failed confirmations show `ERROR …` in *Confirmation Status* and in the Errors sheet. Run `retryFailedConfirmations()`. Failed reminders are retried automatically on the same day's run. Quota: `MailApp` allows about 100 recipients/day on a free Gmail account and about 1,500 on Workspace; the reminder loop stops and logs if quota runs out.

## Email schedule (Africa/Lagos)

| Message | Sent | Who gets it |
|---|---|---|
| Confirmation | On registration, after the row is saved | Everyone, once |
| 3-day reminder | Mon 19 Oct 2026, ~9 AM | Registered on or before 19 Oct |
| 1-day reminder | Wed 21 Oct 2026, ~9 AM | Registered on or before 21 Oct |
| Day-of reminder | Thu 22 Oct 2026, ~9 AM | Registered on or before 22 Oct |
| Follow-up | Fri 23 Oct 2026, ~9 AM | Only if *Consent Follow-up* = Yes or *Request Recording* = Yes. Unsubscribe link included when sent on consent. |

Each send writes `SENT <time>`, `SKIPPED: <reason>` or `ERROR <time>: <msg>` to that message's status column. Only blank or `ERROR` cells are sent, so double-fired triggers cannot duplicate emails. Set *Attendance Status* to `cancelled` to stop all further sends to a registrant. Reminders are never sent after `EVENT_END_ISO`. No extra 30–60 minute reminder is implemented; add it only if the organiser approves.

## Behaviour notes

- **Duplicates:** the server keys on email + event. A repeat registration returns the original ID and sends no second email, so a retry after a timeout is safe.
- **Registration ID** is generated by the server (`FOF-L02-00001`, …) under a script lock. The page shows the confirmation only when the response has `success: true` and an ID.
- **Consent** values are accepted only when exactly `Yes`; the box is never preselected.
- **Poll** posts to the same endpoint and shows success only after the server confirms. Results are not shown on the page.
- **Feedback**: the backend accepts `action: "feedback"` (rating 1–5 required). No feedback page is built yet; point `FEEDBACK_URL` at a form or build one later.
- **Question update** on the confirmation screen is matched on registration ID + email.
